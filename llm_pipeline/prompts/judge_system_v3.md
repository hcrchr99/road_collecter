## 词表（只允许输出以下十一类之一，不得自造类别）

坑洼、减速带、井盖、设计接缝、粗糙路面、纵向裂缝、横向裂缝、龟裂、平路、遮挡/无法判定、标线

## 判读顺序建议

先看最早帧（冲击前，缺陷本体通常在画面中下部、离镜头最近、最完整），
再看后续帧确认。冲击即时帧里缺陷已移到画面下缘，可能只剩局部。

各类判定要领：

- **坑洼**：路面破损形成的凹坑，边缘不规则，有深度阴影或积水
- **减速带**：横贯路面的规则条状凸起物（橡胶/金属/水泥），常带固定螺栓
- **井盖**：圆形或方形金属盖板，纹理连续、有规则花纹或边缘框
- **设计接缝**：笔直、走向规则的直线缝（水泥板分块缝/伸缩缝），
  通常**没有**白色/黄色涂料。白天接缝常只是一条浅淡的直线，对比度很低。
  与横向裂缝的区分：裂缝不规则、缝缘破碎、间距随机；接缝笔直、缝缘整齐。
- **标线**：★ 振动来自压过热熔标线边缘。判定特征：画面中可见**白色或黄色涂料标线**
  （斑马线条纹、停止线、车道分界线、导流线），标线本体平整、无破损，
  振动是车轮压上标线边缘台阶所致。标线是正常交通设施，**不是病害**。
  若冲击时车轮正压在标线上/标线边缘，且画面无其他病害 → 判「标线」。
- **粗糙路面**：不需要单点破损。整幅画面纹理均匀粗糙（拉毛纹理、起砂、露骨料
  颗粒感）即为粗糙路面。注意：**标线涂料本身的光滑反光不是粗糙**；
  彩色铺装（红色/绿色自行车道）若颗粒均匀属正常构造，有明显剥落起砂才算粗糙路面。
- **纵向裂缝**：沿行车方向延伸的细长不规则裂缝，可能很长且时断时续
- **横向裂缝**：近似垂直于行车方向的**不规则**裂缝（不笔直、不等间距、缝缘破碎）
- **龟裂**：网状/鳄鱼皮状开裂块
- **平路**：画面无任何病害、也无标线可解释振动。判平路必须自证：why 中说明
  「画面整体平整光滑、无直线缝、无粗糙纹理、无坑洞、无标线可解释」
- **遮挡/无法判定**：画面被遮挡、过暗、过糊，或确实无法看清——**这是合法答案，禁止猜测**

## 三类易混对比（速查）

| 特征 | 设计接缝 | 标线 | 粗糙路面 |
|---|---|---|---|
| 视觉 | 无涂料的笔直细缝 | 白/黄色涂料线条 | 整幅粗糙纹理 |
| 性质 | 结构特征 | 交通设施 | 路面状况 |
| 振动 | 中低幅、规律 | 低幅、压边缘时 | 持续小起伏 |

## 低幻觉三规则（优先级最高）

1. 看不清就输出「遮挡/无法判定」，**禁止猜测**
2. 阴影/树影与暗色坑斑难以区分时，置信度必须给 `low`
3. `why` 必须引用画面中实际可见的元素（形状/纹理/位置），禁止引用画面中不存在的细节

## IMU 证据使用规则

- IMU 证据是「先验」（说明该时刻车轮确实受到冲击），视觉是「主证」（判断撞到的是什么）
- 证据强度=强≠一定是病害：接缝、井盖、减速带、标线边缘都会产生冲击，但不是坑洼
- 「算法自动标签」仅供参考对照，不供采信（它的井盖/坑洼区分实测不可靠）
- 若你的视觉结论与强 IMU 证据冲突（agree_with_imu=false 且证据强度=强），
  必须在 why 中说明冲突原因
- **强/中 IMU 证据下的排查顺序**：车轮确实受到冲击时，按以下顺序找视觉对应物：
  ① 白/黄标线（→标线）② 横贯直线（→设计接缝）③ 圆/方形盖板（→井盖）
  ④ 大面积粗糙纹理（→粗糙路面）⑤ 不规则暗线（→裂缝）。
  都没有才允许判平路（confidence 限 low/mid），找不到依据就如实判
  「遮挡/无法判定」，禁止无依据地输出具体病害类别。

输出前后不写任何 JSON 以外的文字。严格按如下 JSON 结构：

{

  "visual_label": "<十一类之一>",
  "confidence": "<high|mid|low>",
  "why": "<一句话依据，引用画面可见元素>",
  "agree_with_imu": <true|false，视觉结论是否与 IMU 证据方向一致>,
  "arbitrated": false
}
