# 标注 Schema v1.0

> **这份文件是标注字段的唯一真源。** 任何人、任何 agent 生成标注文件都必须遵守它。
> 不遵守的后果：合并脚本字段对不上，整批标注作废。
>
> 修改 schema 必须升版本号（v1.0 → v1.1），并在下方「变更记录」说明原因。

---

## 0. 怎么产生标注（先看这节）

**不要手写 CSV。** 用 `tools/label_tool.html`：

| 步骤 | 操作 |
|---|---|
| 1 | 浏览器打开 `tools/label_tool.html`（双击即可，无需服务器、无需装环境） |
| 2 | 把采集包 zip 拖进去。全程在本机内存解析，**不上传任何数据** |
| 3 | 填标注者姓名（会写进每一行的 `labeled_by`） |
| 4 | **IMU 事件**页签：逐个事件看画面 + 数值，点真值标签 |
| 5 | **视觉帧**页签：逐帧标真值 + 严重度，看不清就点「标记遮挡/无法判定」 |
| 6 | 点「导出标注」，得到 `<pack_id>.labels.part-<你>.csv` 与 `.frames.part-<你>.csv` |

工具会自动带上 `labeled_by` / `labeled_at`，并跳过你还没标的条目（不会产生的空行）。
键盘 `1`–`9` 对应九个真值标签，`J`/`K` 上下条，`←`/`→` 换帧，`F` 标误报。

进度会自动存在浏览器本地，中途关掉再打开不丢。

> ⚠️ 工具只支持采集端默认的 **STORE 模式 zip**。若报「使用了压缩」，说明包不是采集端原样导出的。

## 1. 两类标注，不要混在一个文件里

本项目的标注分两类，字段完全不同，**必须分成两个文件**：

| 文件 | 标的什么 | 粒度 | 主要用途 |
|---|---|---|---|
| `<pack_id>.labels.csv` | **IMU 事件** | 一行 = 一个已检出事件 | 校准 IMU 检测与分类 |
| `<pack_id>.frames.csv` | **视觉帧** | 一行 = 一张图 | 校准视觉判定、建黄金集 |

混在一起的后果：一个事件对应多张帧，行数对不上，召回率算不出来。

## 2. `<pack_id>.labels.csv` —— IMU 事件标注

### 2.1 字段定义

| 字段 | 类型 | 必填 | 取值 | 说明 |
|---|---|---|---|---|
| `event_id` | int | 是 | — | 事件序号，与 `analyze.py` 输出对齐 |
| `t_start_ms` | int | 是 | — | 事件起始时刻（相对采集开始） |
| `t_end_ms` | int | 是 | — | 事件结束时刻 |
| `peak` | float | 否 | — | 峰值，由脚本填，人工不用改 |
| `imu_label` | enum | 是 | 见 2.2 | 算法给出的分类（**不要手动改**） |
| `truth_label` | enum | 是 | 见 2.2 ∪ `平路` | **人工判定真值**（你的结论写这里） |
| `is_false_positive` | 0/1 | 是 | 0 / 1 | 人工判断这是不是误报 |
| `confidence` | enum | 是 | `high`/`mid`/`low` | 你对这条标注的把握程度 |
| `note` | str | 否 | — | 有疑问、有特殊情况时写，可留空 |
| `labeled_by` | str | 是 | — | 标注人 |
| `labeled_at` | str | 是 | ISO8601 | 标注时间 |

### 2.2 `truth_label` 取值域

```
坑洼      纵向裂缝    粗糙路面
减速带    横向裂缝    平路
井盖      龟裂        遮挡/无法判定
```

- **`平路`** —— 确实没病害（比如只是过了一个小接缝）
- **`遮挡/无法判定`** —— 看不清、镜头糊了、夜间全黑。**这是合法值，不要硬猜**

> 严格区分 `平路` 和 `遮挡/无法判定`。前者是「确定没病害」，后者是「不知道」。
> 把它们混在一起会让准确率虚高（把不知道的都算成对的）。

### 2.3 `imu_label` 与 `truth_label` 的关系

**不要覆盖 `imu_label`。** 保留算法结论 + 人工真值，两者并存，才能算混淆矩阵。

```
event_id,t_start_ms,t_end_ms,peak,imu_label,truth_label,is_false_positive,confidence,note,labeled_by,labeled_at
0,2250,2434,2.97,坑洼,坑洼,0,high,,alice,2026-09-19T10:12:00+08:00
1,3120,3187,5.56,坑洼,井盖,0,high,回看是井盖,alice,2026-09-19T10:13:30+08:00
2,4470,4537,1.47,坑洼,平路,1,mid,应该是接缝,alice,2026-09-19T10:14:10+08:00
```

## 3. `<pack_id>.frames.csv` —— 视觉帧标注

### 3.1 字段定义

| 字段 | 类型 | 必填 | 取值 | 说明 |
|---|---|---|---|---|
| `frame_id` | str | 是 | — | 帧文件名（不含扩展名），如 `frame_000123` |
| `t_ms` | int | 是 | — | 该帧时刻 |
| `source` | enum | 是 | `event` / `sweep` | 事件帧 or 周期扫描帧 |
| `vision_label` | enum | 是 | 见 3.2 | 算法给出的判定（**不要手动改**） |
| `truth_label` | enum | 是 | 见 3.2 | **人工判定真值** |
| `severity` | enum | 是 | `light`/`medium`/`severe` | 病害严重程度（见 3.3） |
| `occlusion` | 0/1 | 是 | 0 / 1 | 画面是否被遮挡/过曝/过暗 |
| `confidence` | enum | 是 | `high`/`mid`/`low` | 你的把握程度 |
| `note` | str | 否 | — | — |
| `labeled_by` | str | 是 | — | — |
| `labeled_at` | str | 是 | ISO8601 | — |

### 3.2 `truth_label` 取值域（视觉）

```
坑洼        纵向裂缝     平路
井盖        横向裂缝     遮挡/无法判定
减速带      龟裂
粗糙路面
```

与 IMU 侧一致，便于融合比对。

### 3.3 `severity` 分级依据

**不要凭感觉分。** 用下面这个可复述的标准，别人复核时才能得出同样结论：

| 等级 | 坑洼 | 裂缝 | 粗糙路面 |
|---|---|---|---|
| `light` | 直径 < 15cm，边缘整齐 | 细缝，宽度 < 3mm | 纹理变粗，无破损 |
| `medium` | 直径 15-40cm | 宽度 3-10mm，或长度 > 1m | 明显起砂、露骨料 |
| `severe` | 直径 > 40cm，或深且边缘破碎 | 宽度 > 10mm，或已形成网状 | 大面积剥落、松散 |

**归到哪级有疑问时，记低不记高，并在 `note` 说明。** 宁可保守。

## 3.5 采集者信息在哪（别和标注者搞混）

这是**两类不同的人**，落在不同的地方，不要合并：

| | 采集者 collected_by | 标注者 labeled_by |
|---|---|---|
| 谁会填 | 骑车采数据的人 | 事后看帧打标签的人（可以是别人） |
| 落在哪 | 包内 `meta.json` 的 `collection.collected_by` | 标注文件每一行 |
| 谁产生 | **采集端第 2 步强制填写**，不填无法开始采集 | 标注工具里填一次，自动写进每行 |
| 性质 | **不可再生的源数据元信息** | 标注产物的一部分 |

**为什么采集者必须随包落盘、不能事后登记**：包一旦导出，就无法反推是谁在什么路况采的。
报告是若干轮之后才生成的中间隔着解压、分析、融合好几步，事后补录等于猜测；
而且报告可被重新生成，身份信息会随之丢失。

**登记表 `MANIFEST.csv` 只是索引**，便于不打开资产就知道团队有哪些数据。
事实源永远在包内 `meta.json`（以及标注文件里）。

## 4. 多标注者一致性（可选但强烈建议）

同一份包由两人独立标注，用来算标注者一致性。**不要合并成一份。**

```
<pack_id>.labels.part-alice.csv
<pack_id>.labels.part-bob.csv
```

然后跑：

```bash
python tools/merge_labels.py --mode kappa \
       --labels raw/<pack_id>.labels.part-alice.csv raw/<pack_id>.labels.part-bob.csv
```

输出分歧清单 + Cohen's Kappa。**Kappa ≥ 0.75 说明标准清晰、标注可信**，
这个数字写进方案文档是加分项 —— 它证明你们的真值不是一个人拍脑袋定的。

对分歧的处理：逐条讨论，结论写进第三份文件：

```
<pack_id>.labels.adjudicated.csv
```

并在 `note` 里写明仲裁依据。

## 5. 黄金集冻结格式

黄金集用 JSON，一帧一个文件，便于逐帧锁定与哈希：

```json
{
  "frame_id": "frame_000123",
  "pack_id": "roadcheck_20260919_0900",
  "t_ms": 45200,
  "source": "sweep",
  "truth_label": "纵向裂缝",
  "severity": "medium",
  "occlusion": 0,
  "note": "",
  "labeled_by": "alice",
  "labeled_at": "2026-09-20T15:30:00+08:00",
  "schema_version": "1.0"
}
```

目录 README 里必须写明冻结信息：

```markdown
- 标注人：alice
- 标注日期：2026-09-20
- 依据：labels/schema.md v1.0
- 帧数：100
- 内容哈希：sha256=8f3a2b1c...
- 状态：FROZEN —— 已用于评估，不得修改
```

## 6. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 手动改 `imu_label` / `vision_label` | 混淆矩阵算不出来 | 结论写 `truth_label` |
| 把「看不清」标成 `平路` | 准确率虚高 | 用 `遮挡/无法判定` |
| 两个 agent 追加写同一文件 | 后写的静默覆盖前面的 | 一人一档，按 pack_id 切分 |
| 严重度凭感觉 | 不可复现，别人复核会得出不同结论 | 按 3.3 的量化标准 |
| 改已冻结的黄金集 | 历史准确率全部失效 | 新建 `golden.v2/` |
| 标到一半发现 schema 不够用 | 已标的要重标 | 先讨论改 schema，升版本号，再继续 |
